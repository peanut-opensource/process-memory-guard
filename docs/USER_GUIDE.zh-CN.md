# Process Memory Guard 2.1.1 使用说明

Process Memory Guard 是原生 macOS 菜单栏进程内存监视工具。它按应用分组保存规则，每条规则有独立阈值；也可以给分组设置可选的“组总内存阈值”，用于约束该组启用成员的内存总和。

## 安装与运行

在仓库根目录执行：

```sh
chmod +x scripts/build.sh
scripts/build.sh
```

脚本会编译 `Sources` 下的全部 Swift 源文件，生成 `outputs/Process Memory Guard.app`，把 `LICENSE` 放入 app Resources 和源码包，运行一次自检，并生成 `outputs/SHA256SUMS`。将 app 复制到 `/Applications` 后打开；首次运行请允许通知。应用没有常驻 Dock 图标，从菜单栏内存芯片图标打开控制台。

## 规则、分组与事件

- 初始规则监视 Apple 的 `remotepairingd`，默认阈值为 1 GB；可以从 `.app` 或具体可执行文件添加更多规则。
- 每条规则直接编辑自己的阈值。组详情显示当前总内存和每个成员贡献，并可设置或清除组总内存阈值。
- 工具读取 `ri_phys_footprint`，同一规则的多个 PID 会相加；不会把虚拟地址空间当成实际内存，也不会自动结束进程。
- 普通规则或组阈值需要连续 2 次达到阈值才启动 `warning` 事件；达到阈值 2 倍立即为 `critical`。低于阈值 85% 连续 2 次才恢复。
- 每个事件记录开始时间、峰值、严重度、通知次数和暂停截止时间。首报立即发送；`warning` 升级到 `critical` 可再报一次；持续超限每 30 分钟最多提醒一次，单事件最多 3 次。通知可“查看详情”（打开并定位规则）、直接输入该规则阈值，或暂停 1 小时。
- `DispatchSourceMemoryPressure` 展示 `unknown`、`normal`、`warning`、`critical`。系统压力只会抬高控制台和菜单栏图标显示，不会单独触发事件。
- 控制台会明确显示：未运行、已禁用、身份失效、正常、warning、critical，并提供当前值、峰值和紧凑趋势。
- 控制台默认自动发现当前用户可读取的全部进程，按完整可执行路径聚合显示 PID、physical footprint 和签名状态，最多展示内存占用最高的 200 条；不需要先手工添加才能看到进程。
- 自动发现只是实时观察，不会悄悄把所有进程变成报警规则。点击某行的“监视”才会把它提升为持久规则，并保存代码签名身份和保守初始阈值。

## 可选 AI 二次分析与隐私

AI 默认关闭。无论 AI 是否可用，本地阈值告警都会立即发出；AI 只在事件已经触发且至少累积 5 个样本后并行追加，失败不会改变事件或本地提醒。每个事件最多约 1 次模型调用，最多发送 10 个样本。

请求 payload 仅包含具体应用组名、规则名称/签名标识、规则与组阈值、采样间隔和 `ri_phys_footprint` 样本，不包含完整进程列表、文件、日志或设备标识；Responses 请求使用 `store: false`。配置面板会披露这些字段和调用规模，并提供“测试连接”“删除密钥”。API Key 只存 macOS 钥匙串。关闭 AI 后自动监视不发起网络请求；“测试连接”是明确的用户操作。

## 状态与安全

目标按完整可执行路径匹配，并在运行时重新校验保存的代码签名身份。身份失效的规则会停止该规则监视，不会切换到其他路径。通知权限被拒绝时，菜单栏和控制台仍可用。
